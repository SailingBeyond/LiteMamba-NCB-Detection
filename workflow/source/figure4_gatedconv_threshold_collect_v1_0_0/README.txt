Figure4：GatedConv 逐6mer阈值统计收集工具 v1.0.0
================================================

本包读取已经运行完毕的六分类 GatedConv 预测，生成一份可上传分析的轻量阈值统计包。它不重新训练、不重新推理、不加载模型或GPU，也不修改原预测、权重、特征缓存或已有 Figure4 结果。当前五分类训练可以继续运行，无需手动暂停。

一、下一步直接运行什么

保留原来的代码和全部结果，把本包单独解压到 paper 目录，然后运行一次：

conda activate pytorch2.0.1
cd /path/to/revision-code/figure4_gatedconv_threshold_collect_v1_0_0
bash launch_collect.sh

入口会先检查已有输入，再在后台提交一个CPU收集进程。终端会打印 PID、独立日志、可以直接复制的 tail -F 命令，以及最后需要上传的文件路径。

看到 [COLLECTION SUBMITTED] 只说明请求已提交；必须等日志出现 [RESULT PACKAGE] 和 [FULL PASS]，才表示统计与打包完成。不要同时再开一份相同收集任务。

如果只想先核对输入而不创建统计输出，可运行：

bash check_inputs.sh

这个预检检查已有文件、身份、元数据和CSV表头。全量CSV内容哈希、逐行概率检查和计数守恒在正式收集时完成。

二、怎样查看进度

复制启动终端打印的准确命令：

tail -F "本次独立日志的实际路径"

也可以在工具目录另开终端运行：

python show_status.py

或者每15秒刷新：

watch -n 15 'python show_status.py'

日志中的 [VERIFY CSV] 表示核对源预测；[SCAN] 表示当前文件的窗口扫描进度；[SOURCE COMPLETE] 表示一个文件已完成；[PROGRESS] 显示已完成文件数。各文件窗口数差别很大，文件完成百分比不等于剩余时间比例。

默认完整输入为216份外部预测加3份验证预测，共219份文件。外部三seed合计21,774,810行，验证集三seed合计1,501,128行，总计23,275,938行。读取、解压、核验和汇总需要一些时间，具体耗时取决于服务器当前CPU和磁盘负载。

在 tail 或 watch 查看窗口按 Ctrl+C，只退出查看，不会停止后台收集，也不会停止模型训练。

三、完成后上传哪个文件

只需要上传这一份：

figure4_gatedconv_threshold_statistics_v1_0_0.tar.gz

默认完整路径为：

/path/to/revision-inputs/CPLX-XNA-replenishment/CPLX-XNA-replenishment/fast5_single_guppy/sixclass_overlap_read_split_721/sixclass_auto_v1_0_4_results/figure4_gatedconv_threshold_collect_v1_0_0/figure4_gatedconv_threshold_statistics_v1_0_0.tar.gz

启动终端和完成日志都会再次打印真实路径；如果显式设置了 output_dir，以打印路径为准。

不用上传原始FAST5、特征CSV、模型权重、数千万行逐窗口预测或 count_cache 文件夹。本工具归档的是小型计数表、指标表和来源核验JSON。上传后再分析不同阈值的收益与代价，决定正文 Figure4 是否采用固定阈值；本包不会先假定严格阈值一定有效。

四、这次统计包括什么

模型固定为最终 GatedConv＋target attention，seed分别为42、2024、2025；六类顺序为 A、T、C、G、X、Y。外部72个数据文件、全部测试组和逐6mer背景都保留，包括原来误报较高的背景和阈值后零接受的背景。

默认扫描15个阈值：

0, 0.5, 0.6, 0.7, 0.8, 0.85, 0.9, 0.92, 0.95, 0.97, 0.98, 0.99, 0.995, 0.999, 1

0保留原无拒判的六分类argmax基线；六分类argmax不是默认0.5阈值。1只是扫描端点，不表示推荐采用阈值1。

每个窗口保留原argmax类别；最高概率大于或等于阈值时接受，否则记作 no_call（不判定）。不判定不会被改成天然类别，也不会从原始分母删除。

原始概率和已有验证集温度校准概率都收集。预先指定校准概率为主要分析，原始概率作为敏感性分析；不根据外部结果择优挑一种，也不在外部数据重新拟合温度。

主要表包括：

threshold_confusion_counts.csv.gz：保留各数据文件、模板、角色、6mer、真值和阈值的六类调用及no_call计数。
context_metrics_per_seed.csv.gz：各cohort、角色、6mer、真值的原始分母、有效召回、误报、保留率及条件准确率。
cohort_class_metrics_per_seed.csv：每组各真值类别的阈值统计。
cohort_metrics_per_seed.csv：每组汇总的天然假X/假Y、X/Y正确身份召回和保留情况。
seed_aggregate.csv：三个训练seed的均值、样本标准差和范围。
validation_threshold_candidates.json：仅根据验证集生成的共享阈值候选，尚未冻结为正式工作阈值。
metric_definitions.json：各字段、分母和限制的定义。
collection_manifest.json、source_provenance.json、evaluation_plan.json及RESULT_PACKAGE_MANIFEST.json：输入、规则、检查结果与文件核验信息。

五、运行资源与原结果保护

程序使用Python标准库，建议在Linux及Python 3.10以上运行，无需安装新依赖。计算流程单进程、逐文件流式读取，只保留紧凑置信度分箱计数，不把全部预测装入内存。验证集只保留阈值选择所需的类别级计数；外部数据保留逐6mer信息。

程序尝试将CPU niceness降至至少10，并通过 ionice 请求空闲I/O优先级。若系统不支持，会在 [PRIORITY] 中记录。低优先级并不等于完全没有资源开销：读取仍会使用少量CPU、磁盘带宽和文件缓存，因此不能保证正在训练的模型耗时完全不变。

默认输出是原外部评估目录的同级新目录，不写回原结果。运行前后核对模型、检查点声明、温度、输入内容身份和文件变化；全量外部预测SHA256必须与先前上传结果中的216份原文件一致，阈值0计数必须复现原2010个联合计数单元。不会自动切换到其他模型、重建预测或读取权重。

六、中断或报错后怎么办

已完整处理的文件保存在新输出的 count_cache 中。重新运行同一个 launch_collect.sh 命令即可继续；重用缓存前仍会重新核对原CSV哈希和来源身份，因此恢复并非完全免读取。

如果日志显示缺少原预测、验证预测或完成记录，保留具体报错和路径用于核查。程序不会因为文件缺失而启动训练或GPU推理，也不会自动排除验证集。不要先删原结果或重新训练。

同一输出目录绑定原输入、参考结果、阈值网格和本包代码。绑定变化时会拒绝写入；如确需分析新网格或新版本，使用新的 --output_dir。--force_rebuild只重建本工具自己的计数缓存，不能绕过来源与绑定核验。

如果当前目录中的输出路径与实际服务器不同，可显式指定：

bash launch_collect.sh --results_dir /实际外部评估结果目录 --output_dir /独立的新统计目录

如果原训练结果目录整体搬迁，--training_root用于显式指定新的共同训练结果根，按冻结路径相对关系映射，不自动搜索其他运行。正常情况下不用设置；不确定时保留缺失路径报错后核查。

仅在明确只做外部探索时，才使用 --external_only。这个选项不收集验证集，结果不能用于选择正式工作阈值，不是缺文件时的自动修复方法。

需要前台运行同一流程时：

bash run_collect.sh

七、解释结果时必须保留的边界

误报和有效身份召回的分母为全部原始窗口；保留部分准确率必须与保留率一起看，零接受时条件准确率为NA。提高阈值能减少被接受的错误，也会丢失部分正确调用，不能只展示过滤后留下的窗口并称整体性能提高。

共享阈值候选只根据验证集计算，预设天然假X/Y目标为1%、0.5%和0.1%，要求三个seed均满足约束。它只是验证集候选，不能保证外部数据达到相同误报水平；不可达到或使某靶标有效召回为0的情况会单独标记。

外部Figure4结果此前已经查看过，本次外部扫描属于事后敏感性分析，不应称为新的盲测。不能依据每个外部cohort或6mer分别挑选最有利阈值。原始基线应保留为前后对照，是否正式改图需要等这份统计结果完成后判断。

XNA17–20没有天然对照，天然误报率仍不可估计。三个seed反映训练变化，不能当作生物学重复；对缺少真实read身份的记录不伪造read级置信区间。本次仍是窗口层面分析，也不会因为加阈值而成为未见过6mer的泛化测试。
